▶ The one URL

http://192.168.1.130:8060/news.m3u8
Open in VLC (iPhone / Mac / Windows: Open Network Stream → paste → play), IINA, Safari, or PotPlayer. The player and palazzo must be on the same home network (192.168.1.x). No account, no token, no script needed on the player side.

1. How the stream is obtained (the endpoint)

A single public call resolves the live stream — no login, no API key, no auth header: 
POST https://news.tvb.com/app/public/live/stream/C
Content-Type: application/json   Body: {}
{ "data": {
  "stream_url": "https://edgeware-live2.edgeware.tvb.com/…/index.m3u8?sig=…&mode=admarker,ticks",
  "protocol": "hls", "quality": "hd", "refresh_interval": 3600, "geo_blocked": false } }
Only live channel is C (無綫新聞台 / Channel 83). The URL is time-signed and expires in ~1 hour — this is the whole reason a stable proxy exists.

2. The media (Edgeware HLS)

Following the master URL redirects to a per-session Edgeware edge. Variants:
VariantResolutionBandwidth
3/v15000001280×7201.71 Mb/s
3/v10000001024×5761.20 Mb/s
3/v400000480×2700.59 Mb/s
3/a128000audio128 kbps
Segments are ~8s H.264 at 25 fps. Every media stream is AES-128 CBC encrypted, and the decryption key is a public 16-byte file (https://ads.cdn.tvb.com/newskeys/live.key) — so the whole chain plays in any HLS player without credentials.

3. What the proxy does

The signed URL expires hourly; a media player can't re-mint it. The proxy connects the two:
  1. POSTs the stream endpoint for a fresh signed URL.
  2. Follows the CDN redirect to the current session edge.
  3. Rewrites the HLS playlists so every variant, segment and the AES key are re-served through this same proxy — players never see the CDN or the signed URL.
  4. Re-resolves a fresh signed URL before expiry (every ~55 min). To the player it's one fixed URL forever.
Runs as a systemd service (tvb-proxy.service): auto-starts, auto-restarts, survives reboots.

6. Browser player (works too)

The same stream also plays in a browser via hls.js (stream hosts send Access-Control-Allow-Origin: *). The companion report.html ships a self-contained player (hls.js inlined, no CDN). To make it work you must first fetch the master to follow the Edgeware 302 and feed the resulting session URL to hls.js — hls.js does not follow cross-origin redirects itself.
